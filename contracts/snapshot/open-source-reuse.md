## 二、开源复用清单（详细）

### O1. Spring AI —— 引擎内模型客户端

- **是什么**：Spring 官方 AI 应用框架：ChatClient 统一多供应商对话调用、流式响应（Flux）、工具定义抽象、结构化输出转换。
- **架构位置**：引擎层 ModelGateway 的底层，被 AgentDriver/FlowDriver 的 LLM 调用使用。
- **承担**：OpenAI 兼容端点对接（DeepSeek 云 API/本地 vLLM/Ollama 全部收敛为同一协议）、SSE 流式解析、消息模型（System/User/Assistant/ToolResponse）、每次调用的参数装配。
- **明确不承担（边界）**：**工具调用循环的自动执行**。平台自研 AgentDriver，守卫校验、版本绑定、trace、预算扣减都必须包在每次调用外层——因此只使用 Spring AI 的"单次对话"能力，关闭其自动工具执行（ToolCallingChatOptions 内部管理模式），工具调用结果由我们的执行器产出后手工回灌。
- **注意**：迭代较快，锁定 1.0.x GA 并在其上封一层自有接口 `LLMClient`，防止框架 API 变动穿透引擎。
- **替代**：langchain4j；或自封装 OpenAI 兼容 HTTP 客户端（不建议，等于手写弱化版 Spring AI）。

### O2. AntV X6 —— 画布编排引擎

- **是什么**：蚂蚁开源图编辑引擎，专做可交互的节点连线画布。
- **位置**：前端构建中心。
- **承担**：画布渲染、节点/边模型、拖拽、连接桩与连线规则、框选/对齐/小地图、撤销重做、JSON 序列化。
- **不承担**：节点属性面板表单、图契约校验、调试状态渲染——自研；且 **X6 的 toJSON 产物是"画布展示数据"，需转换为图定义契约的"业务定义 JSON"**（两者分离，对应评审第 3 条）。
- **选型理由**：中文文档完善、流程图场景成熟、Vue/React 支持均好（x6-vue-shape / x6-react-shape）。
- **替代**：React Flow（xyflow）、LogicFlow（滴滴）、Rete.js。

### O3. jtokkit + 三档计量 —— token 计数

- **是什么**：Java 版 tiktoken（OpenAI tokenizer）实现。
- **位置**：支撑层，上下文组装器的计数后端。
- **v3.5 边界收紧（评审 2 的落实，dsh 文档同样警示）**：固定密度与精确计数**都不可直接作为请求准入或计费依据**——固定密度对中文与 JSON Schema 会显著低估。**计量分三档**：①估算档（jtokkit 或固定密度）只用于容量规划与分账展示；②**准入档**：按部署模型的适配计量（模型插件 tokenizer / 服务端 `/tokenize`）+ 保守余量，判定能否发送；③**对账档**：以供应商回包 usage 为准回写；**校准系数不跨模型/工具集/请求格式复用，变更后重新校准**。
- **复用**：jtokkit（OpenAI 系精确计数）；**vLLM `/tokenize` 端点**（服务端精确计数，准入档首选——多一次网络往返，但准入是低频判断，可接受）。
- **替代**：HF tokenizers Java 绑定（重，JNI 依赖）。

### O4. Resilience4j —— 容错机制

- **是什么**：轻量容错库：Retry / CircuitBreaker / RateLimiter / Bulkhead / TimeLimiter。
- **位置**：技能执行器、模型网关。
- **承担**：**机制层**——超时控制、重试调度（指数退避）、按供应商熔断、模型/技能/DB 舱壁独立池。
- **边界（评审第 2 条的落实）**：**只提供机制，不提供决策**。能否重试由技能契约的"错误语义+幂等性"决定：只读失败可重试；写操作超时不走自动重试，进"结果未知"对账流程；重试只在引擎统一一层，SDK/网关/K8s 不各自重试。

### O5. MCP Java SDK —— 工具协议

- **是什么**：Model Context Protocol 官方 Java SDK，JSON-RPC 协议（stdio / Streamable HTTP 传输）、能力协商、工具列表与调用。
- **位置**：技能中心适配器层。
- **承担**：**Client 能力（一期）**：接入外部 MCP 工具，拉取工具清单自动生成技能注册草稿；**Server 能力（二期）**：把平台技能以 MCP 端点暴露，供外部智能体/工具软件调用。
- **注意**：Client 与 Server 是两项独立能力分两期建设；协议版本与传输方式写进《技能调用契约》。

### O6. swagger-parser —— 接口文档转技能

- **是什么**：SmartBear 开源的 OpenAPI/Swagger 解析库。
- **位置**：技能注册向导。
- **承担**：已有 HTTP 服务贴 OpenAPI 文档 → 解析接口+参数 Schema → **自动生成技能注册草稿**；人工只需补"面向模型的功能说明"与守卫属性声明。
- **价值**：这是"注册成本决定平台可用性"的关键减负件。

### O7. 可观测全家桶：OpenTelemetry + Prometheus + Grafana + Loki + Tempo

- **位置**：横切可观测面。
- **承担**：OTel SDK 埋点（每次调用一个 span，业务键=run_id）；Prometheus 存指标（运行数/耗时/token/错误率）；Grafana 看板；Loki 聚日志；Tempo 存跨服务链路（引擎→网关→技能）。
- **边界**：全部自部署；**业务 trace（run/node_instance/attempt）是自研表**，OTel span 以 run_id 为关联键挂接，Grafana 里做"业务记录 ↔ 基础设施 trace"跳转。
- **交付策略（已决策）**：随平台一并交付部署，定位为交付方运维排障设施，数据留在客户环境；**对客户业务用户不暴露**（仅运维网络可达、不进门户导航、不写用户手册）；客户侧监控统一用自研"运行中心"页面。

### O8. MinIO —— 对象存储

- **位置**：基础设施。
- **承担**：文件技能输入/输出、算法产物、调试快照的存储。
- **配套自研**：artifact 元数据表（引用/大小/类型/SHA-256/归属/保留期/下载授权）；**桶按租户分前缀**（tenant 贯穿存储路径）；下载走预签名 URL+归属校验；**物理路径永不进入 prompt 与用户界面**（结果隔离第 4 锁）。

### O9. Keycloak（可选）—— 身份与信任根

- **承担**：平台用户认证（OIDC）、出票 JWT 的验签信任根、GuardContext 的权限属性源（区域/部门/密级属性放 Keycloak 用户属性或组）。
- **决策点**：目标环境已有统一身份源/4A 时，**对接优先于新建**；都没有则部署 Keycloak，避免自管密码与会话。

### O10. networknt json-schema-validator —— Schema 校验

- **位置**：三处布防——技能执行前参数校验、发布前图定义校验、LLM 结构化输出校验。
- **要点**：统一 Schema Draft 版本；校验失败错误信息要**翻译成模型可读的回灌文本**（参数错→带原因重试）。

### O11. amis（可选）—— 管理页面低代码

- **承担**：系统管理、统计报表等 CRUD 型页面加速。
- **边界**：画布、调试面板、对话页**不用** amis（交互复杂度不适合），手写组件。

### O12. One-API（可选）—— 供应商管理面

- **是什么**：Go 开源 LLM 网关：多供应商统一为 OpenAI 兼容端点，Key 托管、配额、用量统计、管理界面。
- **职责澄清（评审第 11 条的落实）**：**与 Spring AI 不是同层二选一**——Spring AI 是引擎内模型交互客户端；One-API 是服务端 API 管理与分发面。两者可并存：引擎 → One-API → 各供应商。
- **决策点**：起步期直接部署省自建；当需要深度定制（数据出域路由、细粒度背压、租户级报表）时，自建网关面、One-API 退为参考。替代：LiteLLM Proxy。

### O13. Kubernetes Java Client —— 算法任务

- **承担**：算法技能的 Job 提交/状态查询/日志拉取。
- **配套自研**：**确定性命名防重**——Job 名 = `alg-` + hash(幂等键)，同幂等键重试只会命中已有 Job，天然防重复启动（执行语义第 2 条的 K8s 落地）。

### O14. Flyway —— 数据库迁移

- 契约 → DDL 的落地工具；四份契约对应的建表迁移脚本纳入版本管理。

### O15. 参考源码与参考产品（不依赖、只借鉴）

- **Dify**（Python）：**平台层对标**——流程解释器的节点类型/变量上下文/重试策略、调试交互、配置模型、发布与统计形态。
- **DeepSeek Harness（dsh，MIT，TypeScript）**：**运行时机制首要参考**（本地克隆 `D:\00-Work\02-Application\01-CodeIDE\deepseek-harness`）——`core/system-prompt` 组装分节注册表、`core/session` 会话日志不变量（"Model-visible means logged"）、`compaction` 压缩家族（修剪器/摘要后端/手动命令分离）、`llm/token-meter` 固定密度计量、`core/tools` 工具执行守卫管道。MIT 允许代码复用，但 TS 实现 ≠ Java 引擎，以读码吸收为主；已吸收六点进主设计 §6.1。
- **LangSmith**（LangChain 家，SaaS/可自托管）：**观测与评测层参考**——run 树/feedback/dataset 三元数据模型（直接对照我们的 run/node_instance/attempt 与主设计 6.9 评测）、评估数据集+自动评测+人工标注+版本对比的产品形态（M4 评测轻量版与二期的参照）。注意：它不做画布构建、不托管运行——与我们互补而非重叠。
- **Coze（扣子，字节跳动）**：**平台层同类竞品**——画布编排/插件商店/知识库同构；其差异项"一键发布到飞书/微信等渠道"是渠道分发的成熟形态，值得我们的发布与集成层借鉴。
- **ZCode / Codex**（闭源）：交互与行为黑盒基准——观察其长会话裁剪、工具清单取舍、确认交互，校准我们自己的策略预期。
- **LangGraph4j**：Java 图编排抽象，参考其状态图设计。

### O16. Monaco Editor / CodeMirror 6 —— prompt 全文查看器

- **是什么**：开源代码编辑器组件（VS Code 同源内核 / 轻量 CodeMirror）。
- **位置**：调试面板（册 32）的 LLM 节点检查器——只读展示组装后的 prompt 全文、工具 Schema、装配清单。
- **用法**：只读模式 + 搜索/高亮/行号/折叠；**不带编辑能力**（prompt 在组装器里已冻结）。

## 三、纯自研清单（实施设计思路与细节）

### S1. AgentDriver —— 对话型受控循环

- **职责**：对话型智能体的循环推进与终止判定（设计文档 §2/§6.6）。
- **核心设计**：
  - 循环骨架：`组装 → LLMClient 流式调用 → 解析 → [工具调用？执行→回灌→下一轮 : 最终回答]`，每轮过预算检查器；
  - **终止规则引擎**：六种情形各一个处理器（纯文本终止/混合返回先执行工具/截断按策略/非法参数带错误回灌计步/未知工具回灌纠正/无进展熔断）；
  - **无进展检测**：最近 N 轮调用做 `(skillId + 规范化参数 hash)` 指纹，连续重复即熔断；
  - **四类预算**：总耗时 deadline、模型调用次数、token 累计、嵌套深度——每轮前置检查，超限走熔断分支（区别于异常终止，答复中说明"因预算停止"）。
- **关键难点**：流式响应与工具调用的分帧（一段流里既有文本又有 tool_call 分片）——用增量解析器边收边组帧。
- **接口形态**：`LoopResult drive(RunContext ctx)`，RunContext 含会话历史引用、技能清单、预算、GuardContext。
- **验收**：终止规则用例组每情形一条（含"文本+工具并存"与"连续无进展"两条刁钻用例）。
- **工作量**：M（2~3 人周）。

### S2. FlowDriver + DAG 解释器

- **职责**：解释图定义契约，推进流程型运行（§2 双驱动器之一）。
- **核心设计**：
  - **编译期**：flow_definition JSON → 内存图模型（节点表+边表+执行规则对象）；发布校验在此模型上做（类型/无效引用/并行同名写/守卫声明）；
  - **就绪判定**：节点入边全部到达终态（成功 或 SKIPPED 传播）即就绪；条件分支未命中 → 下游标 SKIPPED，汇合节点按声明语义（ALL=全部成功或跳过 / ANY=任一成功）放行；
  - **并行执行**：就绪节点集合并行提交（虚拟线程或 worker 池），互不共享可写变量（图契约保证）；
  - **变量上下文**：`按作用域分层的类型化键值`（全局作用域+节点输出槽 `node_X.output`），取值 JSONPath；发布期类型检查+运行期宽松转型；
  - **失败语义**：按节点配置三分支——终止运行 / 走错误边 / 输出默认值继续；
  - **节点处理器注册表**：`Map<nodeType, NodeHandler>`，LLM/技能/条件/代码/检索各一个实现，新增节点=注册新处理器（模块 2 预留点的落点）。
- **关键难点**：并行汇合+分支超时的组合语义；SKIPPED 在汇合节点的传播规则——这两条是《图定义契约》必须写死的部分。
- **参考**：Dify workflow 源码、LangGraph4j。
- **工作量**：L（4~6 人周）。

### S3. 上下文组装器 + Token 预算分配器

- **设计**：组装管道五步——系统提示渲染（词表提供者接口在此注入）→ 工具 Schema 注入 → 历史装填（预算内从新到旧）→ 裁剪管道（四档，保持工具调用/结果配对）→ 计数复核。`TokenCounter` 接口双实现（jtokkit 精确 / 估算+校准），usage 校准器后台滑动修正系数。
- **dsh 六点吸收（v3.5，详见主设计 §6.1）**：①系统提示**分节注册表**（名称+序号约定+作用域遮蔽+组装瀑布=守卫裁词表实现位）；②**动态上下文快照投影**（按类型/作用域/版本只取最新有效版进请求，历史留审计；分节遮蔽白名单+改写后重校验工具集）；③**严格变量插值**（未知/未定义 fail-fast）；④**计量三档**（估算档只做展示、准入按模型适配计量、usage 对账——见 O3）；⑤**压缩家族解耦**（工具结果修剪器无模型零成本先行，摘要仅仍超限时触发）；⑥**可重建不变量**（凡进模型请求必可从 run 消息日志重建，先落库再发请求）。
- **难点**：摘要压缩的同步等待会拖首 token 延迟（一期同步实现，二期异步化预生成）。
- **工作量**：M（2~3 人周）。

### S4. 技能注册中心（六维能力契约）

- **设计**：六维契约的字段模型（见主设计 §5 skill_version）+ 注册向导（swagger-parser 导入 → 生成草稿 → 人工补功能说明与守卫声明 → 连接测试 → **选型验收**：给 10 条典型测试问题，断言模型选中本技能且参数抽取正确）→ 上架版本。
- **渲染器**：技能契约 → 模型工具定义（JSON Schema → function definition），含说明书写作规范的内嵌引导（能力句/适用/不适用/参数示例）。
- **难点**：功能说明质量的量化验收——用固定测试问题集跑选型，作为上架门禁。
- **工作量**：M~L（3~4 人周）。

### S5. 技能执行器 + 三适配器

- **设计**：统一入口 `execute(skillVersion, args, GuardContext, 幂等键) → ResultEnvelope`：
  - **HTTP 适配器**：RestClient 调用 + 守卫注入点（查询守卫追加过滤条件）+ 错误分类映射表（HTTP 状态/业务码 → 五类错误语义）；
  - **MCP 适配器**：MCP Client 调用；
  - **算法任务适配器**：K8s Job 确定性命名提交 → external_job_binding 登记 → 状态轮询/回调双通道 → 产物转 artifact 引用；
  - **对账器**：写操作超时进"结果未知"→ 按技能契约的对账方式（查询端点/状态接口）核实 → 未生效则重试、已生效则采纳；
  - **大结果处理**：超阈值转 artifact 引用+摘要；**接收即计数、有界缓冲、流式转存**（不得先整体读入再判断，LRU 缓存限总字节量，主设计 §6.3 硬闸①）。
  - **迟到结果与调用级检查点（v3.2 增补）**：Agent 节点检查点细化到**每次模型调用、每次工具调用与结果提交**（含预算消耗与待处理调用）；旧 attempt 的迟到结果必须**验签+归属校验+留痕并参与同一幂等键下的对账**——不能仅因 attempt 旧就丢弃成功事实；逻辑结果经租约校验+归属+输出校验后**原子提交一次**，下游只消费已提交结果。
- **验收**：守卫拦截演示 + 写技能超时对账不重复执行演示（M1 验收项）。
- **工作量**：L（4~5 人周）。

### S6. 模型网关面（供应商管理）

- **一期**：部署 One-API（供应商 Key/配额），引擎侧 Spring AI 指向它；数据出域路由在引擎侧做（按数据标记选本地/云端端点）。
- **二期（按需）**：自建网关面——令牌桶（供应商 TPM/RPM）、应用/用户配额表、排队与预计等待、租户计量报表；One-API 退为参考。
- **工作量**：一期 S；二期 M。

### S7. 运行调度器（认领/租约/接管）

- **设计**：
  - 步骤任务表即队列：就绪步骤写入待执行表；副本用 `SELECT ... FOR UPDATE SKIP LOCKED` 认领；
  - **租约**：认领时写 lease_owner + lease_until，执行中定时续租；租约过期 → 其他副本可接管（旧副本提交带租约校验，失联提交被拒）；
  - **优雅停机**：停机钩子先停止认领 → 在途步骤执行完（或租约到期自然转交）→ 退出；
  - **优先级分池**：交互/批量两个队列与 worker 组，互不挤占。
- **难点**：租约校验与状态更新必须在同一事务（防"状态改了、租约没算"的竞态）。
- **工作量**：M~L（3~4 人周）。

### S8. 执行语义组件

- node_instance/attempt 生命周期管理；幂等键生成（`hash(run_id + node_instance_id + 规范化参数)`，跨尝试稳定）；结果未知对账器；取消三态传播（请求取消→外部停止→效果撤销的记录链）。
- **v3.2 增补**：Agent 调用级检查点（细化到每次模型调用/工具调用与结果提交）；**逻辑结果唯一提交**（租约校验+归属+输出校验后原子提交，下游只消费已提交结果）；**双驱动结果投影**（对话型投影到会话历史、流程型按节点依赖投影到输出槽——统一结果组装器，对话历史不是流程取值的唯一来源）。
- 工作量：M（2~3 人周）。

### S9. 守卫解析器

- **设计**：GuardContext 解析（IAM 属性快照+TTL）→ 交集运算（模型提议 ∩ 授权集，默认拒绝）→ 四类数据源强制点实现（查询守卫 SQL 注入器 / 令牌交换客户端 / 存储前缀校验 / 算法输入清单校验）→ 守卫审计留痕（谁/属性/授权集/实际范围）→ 数据出域标记检查。
- **验收**：越权拦截用例（M1）+ 撤销时滞用例（M4）。
- **工作量**：M~L（3~4 人周）。

### S10. 调试控制器 + 事件流

- stepController 节点前钩子（全量/单步两模式）；WAITING_STEP 持久化与恢复；**事件表 + SSE 通道**（事件自增 ID，断线重连带 Last-Event-ID 补发，消费端去重）；resume 接口幂等；技能 Mock 管理；断线不杀任务策略。
- 工作量：M（2~3 人周）。

### S11. 人工确认控制器

- WAITING_APPROVAL 状态机；确认人路由（按角色/租户解析）；参数快照与变更重确认；有效期超时器；确认中心待办页数据源。
- 工作量：M（2 人周）。

### S12. 发布与版本管理

- 草稿/发布双轨状态机；发布检查器（结构/参数/类型/无效引用/守卫声明的图模型级校验）；SHA-256 摘要；快照记录（流程定义版本+解释器兼容版本+依赖版本）。
- 工作量：M（2~3 人周）。

### S13. 集成套件

- **assistant.js（Web Component）**：悬浮球→侧滑抽屉→流式对话（SSE）→结果卡片（按富载荷类型渲染）→历史会话；主题配置驱动外观；
- **出票验签服务**：集成密钥 JWT 验签 + 声明范围上限裁剪（越界属性丢弃并告警）+ principal 构造；
- **片段生成器**：门户上按应用自动生成接入代码。
- 工作量：L（3~4 人周，组件本体最大）。

### S14. 画布前端

- X6 集成、节点注册与渲染（按节点类型注册 Vue 形状组件）、属性面板（按节点类型的表单 Schema 驱动生成）、图契约的双向转换（X6 数据 ↔ 业务定义 JSON）、调试联动（事件驱动节点变色、点击查看输入输出）。
- 工作量：L（4~6 人周）。

### S15. 管理门户页面群

- 工作台/应用列表/生命周期操作/模板库/技能库/统计报表/确认中心/系统管理；CRUD 页可用 amis 加速，交互页手写。
- 工作量：M~L（4~6 人周）。

### S16. 四份契约文档（M0 交付，决定一切代码的形状）

1. **图定义契约**：结构 Schema（节点/边/属性）+ 执行规则（并行/汇合/跳过/错误分支/循环边界）+ 类型规则（变量作用域/空值/数组映射/转型）；
2. **trace 模型**：run/node_instance/attempt DDL + 状态机 + 与 OTel 的关联键；
3. **技能调用契约**：六维契约字段规范 + 错误语义分类表 + 幂等键与对账协议 + MCP 对接方式；
4. **授权与人工确认规范**：守卫属性模型、交集原则、WAITING_APPROVAL 全规则、数据出域规则。

## 四、复用与自研的边界原则（决策规则）

**判断规则一句话：通用协议、成熟机制、基础设施 → 复用；携带业务语义的契约、编排、治理 → 自研。**

五个容易踩错的边界案例（写进编码规范）：

1. **Spring AI 只当客户端**：工具循环绝不交给框架自动执行——守卫、版本绑定、trace、预算必须包在我们自己的循环里（评审第 11 条）；
2. **Resilience4j 只当机制**：重试决策由技能契约驱动，框架不知道"这个调用能不能重试"；
3. **Spring AI 与 One-API 职责分离**：引擎内客户端 vs 服务端管理面，不写成二选一；
4. **jtokkit 不做真相**：计数只做预算分账，以服务端 usage 校准；
5. **amis 不进复杂交互页**：画布/调试/对话手写，低代码只管 CRUD。
