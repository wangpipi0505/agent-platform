原函数无论 DACL 是否已经符合要求都会重写，并把 `Get-Acl` 返回的安全对象传回 `Set-Acl`。第二轮在重启时重复设置已私有日志权限出现 `SeSecurityPrivilege` 异常。纯文件试验进一步证明：仅换成全新 `FileSecurity`、仍经 PowerShell 5.1 `Set-Acl` 写入已受保护文件，也会出现同一异常；不能把“新对象”单独视为已验证解决。

最终函数先准确判断 DACL：必须 Protected，当前用户 SID 与 SYSTEM 各且仅一个显式 `FullControl Allow`，无额外规则、无 inherited ACE、`PropagationFlags=None`；文件 `InheritanceFlags=None`，目录为 `ContainerInherit,ObjectInherit`。完全符合才直接返回。

不符合时新建 `FileSecurity` 或 `DirectorySecurity`，仅构造上述受保护 DACL，通过 `[IO.File]::SetAccessControl` / `[IO.Directory]::SetAccessControl` 持久化。没有回写 Get-Acl 对象，也没有设置 owner、group 或 audit。以下实测确认 owner/group 保持不变；未申请审计权限或读取 SACL，不声称做过 SACL 检查。
