## 已复验的修复

- 运行观察查询显式枚举授权列，状态和元数据读取不加载原始评测候选。评测实际执行继续读取并校验候选。
- 会话、运行准入和共享测试库增加隔离。高危操作按两名已验主体审批，真实执行仍要求当前授权。
- 迁移校验验证历史版本确实执行；HTTP 和审计测试采用现行 Spring 注入、证书、授权范围及日志设置。
- SSE 容量探针在检查前开具短票，保留帧、读权限和槽位占用与释放断言。
- 独立 CHAT 联测在故障恢复后读到引擎持久化的 `FAILED / MODEL_RESULT_UNKNOWN` 和模型调用 `UNKNOWN`，没有模型重发。

## 本机复跑入口

在当前项目 `.local/r50-20261127` 执行 `python -X utf8 suite.py <新轮次名>`。脚本创建隔离 PostgreSQL、Redis 和临时证书，从当前工作树执行 `mvn -pl engine-runtime test`，保留 Surefire 原件并回收临时容器。子进程类路径为当前工作树 app、model、engine 与 admin-common 各自的测试及生产编译目录。

发送联测使用 `sender-batch.py`，CHAT 联测使用 `chat-batch.py` 和同目录已编译的组件夹具。复跑时将 `R50_TLS_ROOT` 指向新轮次的证书目录。一次只运行本机本项目的隔离轮次，直接 JUnit 结果按实际测试方法核对。三个 `RunAuthorityLiveResumeTest` 受原有 `EX26_LIVE_RESUME` 真签发服务配置控制，本轮沿用其原有跳过条件。

本轮测试在本机隔离环境执行。R-22 发布负责人的正式门禁保留待核对。
