## 1. 状态口径与完成判定

| 状态 | 含义 |
| --- | --- |
| 待启动 | 本次明确的增补范围尚未开工；可以存在历史组件，不等同于整个能力没有代码 |
| 待核实 | 历史登记与当前源码未逐项核对；先复现/盘点，再判需补实现或可验收 |
| 进行中 | 已开工，关闭条件未全满足（必须写"剩余"） |
| 待验收 | 代码 + 定向测试 + 证据目录齐备，等待复跑/评审 |
| 完成 | 关闭条件逐条有当次证据，**且** 提交号、证据路径、复跑命令与数字已回填，经过评审 |
| 暂缓 / 冻结 | 明确不做或等外部条件（须写原因与解冻条件） |
| 阻塞 | 需外部输入，已写明具体条件与已尝试动作 |

**DoD（标 `完成` 的五条，缺一不可）**：①功能修复的关键失败路径先红后绿；纯盘点/文档/验收卡不制造红阶段，以实际复验或文档校验记录替代并标适用性；②模块级回归不新增坏类（附合计数字）；③`docs/evidence/<日期>-<项>/README.md` 含命令原文与测试数字；④经一次独立只读评审（同一份证据即可；人员资格、模板和未通过处理见§14.4）；⑤提交号 + 回滚方式写入本表（有开关写真实键，无开关写恢复提交/兼容方案，禁止编造开关）。

**回归统一口径**：定向与本卡原失败场景必须通过；模块回归按EX-00冻结的同环境方法清单，新增失败方法/坏类/跳过/未执行=0。保留的基线红逐名归因并关联EX-27；不要求无关卡先清空所有存量红，也不能用“总数相同”或 `failure.ignore` 的 BUILD SUCCESS代替通过。评审、代码、证据必须覆盖本卡全部范围。

**主项与组件**：子项局部绿不等于主项完成。主项仍有本版明确残项时为进行中；组件实现/证据已齐但缺复验为待验收；已完成历史记录在EX-08复核，不自动抹除已有成果。

### 7.1 D-02 裁决：全局资产进入冻结包的规则（2026-10-28，默认规则，待评审会追认）

**问题**（原 R13 阻塞原因）：码表、共享概念、共享关系等"全局资产"是否允许进入 release 冻结包？若允许，变更时是否阻断发布？

**裁决（默认规则，未追认前按此实现）**：

1. **允许进入，但必须按值快照**：冻结包里存 `assetRef + assetVersion + sha256` 的自包含快照，**不允许只存引用**（否则冻结包会随全局资产漂移，"冻结"失效）。
2. **记录来源与覆盖链**：快照要写来源空间与是否被本地同名资产覆盖（override 链），供影响分析区分"本地改动"与"共享资产变更"。
3. **变更只报不阻断**：全局资产变更**不阻断**发布，由 R13 的实例影响分析产出受影响实例清单，`CRITICAL` 级进 REVIEW 材料；这与 R13 原设计"进 REVIEW 不阻断"一致，不新增门禁。
4. **删除/弃用不算失败**：全局资产被弃用或删除时，冻结包内快照仍可用；引用完整性问题由 `integrity-check` 报 `GLOBAL_ASSET_MISSING`，不得让发布失败。
5. **谁负责追认**：D-02 属本体侧评审项，由本体 owner 在评审会追认；追认前按本规则实现，追认后若规则变化只需改 R13 的分级判定，不动冻结包结构。

**对 O-04 的连带影响**：发布报告里的 `affectedApps` 已有；R13 落地后应把"共享资产变更"并入同一份影响材料，避免两套影响清单。

**本期最小集口径**：O-02/O-03/O-05/O-07（+ X-9 定案新增的 O-11、X-11 定案新增的 O-12）共 9–14 人日（方案 §11.9 阶段 B），与 agent-platform S2/S3 并行；其余 6 项只做接口预留，不排期。O-09 只补"空间 A 的 ontopa_ key 打空间 B → 403"一条负例。
