## 已确认的缺陷

- **P1：原始 Schema 字节数和位置数不能限制引用展开工作量。** 独立审查在隔离的有限堆子进程中观察到，小体积、位置数低于原限额的共享定义引用图进入 networknt eager 初始化后发生 `OutOfMemoryError: Java heap space`。根任务已读取原日志，栈位于引用与组合校验器初始化；不能依靠 64 KiB 原文或 4096 个位置保护该阶段。此处不记录探针载荷或再次执行资源耗尽测试。修复要求是在构建 native validator 前，以饱和计数限制引用图展开工作量，并明确处理环、anchor 和资源边界。
- **P2：不可信正则的计算时间未被 HTTP deadline 限制。** 独立审查的已预热局部用例在 800 ms 配置预算下耗时约 7311 ms。HTTP 超时不能中断同步 Java 正则计算。日志中的调用计数包含预热阶段，不能据此声称超时后发送了业务请求。修复须提供可解释的有界正则执行机制，明确拒绝不支持的模式，不能在返回超时后留下无界后台计算线程。

另有连接清理候选待核实：现有 close 的短暂 join/await 返回后，没有明确确认 reader/HttpClient 实际退出，适配器即归还许可。远端连接稍后关闭本身不足以证明客户端线程泄漏。本项须以本地资源退出和许可生命周期的安全测试核验，当前不作为已复现泄漏结论。
