# G6 只读计划的实施裁决

2026-10-20，root 阅读 `iam-service-authority-implementation-plan.md` 后作以下技术移交裁决。本文是后续内部软件实现的约束，不是已实现、已测试或生产 IAM 签收。

1. **接受首版客户端适配 profile。** 本工程消费外部可信 IAM/授权服务的受限 token exchange、持久 grant 引用、当前决定及批准者权限证据；按计划固定版本化内部 DTO 和签名/nonce/caller/target/action/resource/subject 绑定。RFC 8693 不天然提供 grant 恢复/当前权限/独立批准者核验，不能把这些建议字段当作标准事实。本工程只写客户端与测试目录中的有限 issuer/authority，不新增生产 IAM 服务端。真实部署必须接等价能力并另行签收，缺能力的动作默认拒绝。
2. **接受有边界的集成桥接。** 保持 ApiKey/SDK 对外协议与≤300秒短票据。由可信 gateway 身份和独立当前 app policy resolver 证明 credential/主体/应用/属性上限；authority 与 resolver 的机器动作和签发域隔离，不循环借尚未签出的用户票据。业务服务不能接受 gateway 自报 Actor，不能把集成 HMAC 当内部服务验签回退。先做有限真实协议夹具；没有实际 IAM profile 不启用生产桥接。
3. **旧运行默认拒绝自动补权。** 无有效 grant 引用或当前证据的旧运行/事实不得用 PG 旧 Actor 自签票恢复、重发或自动补录授权。保留原事实/委托历史和明确阻断原因。历史查看/下载仍须当前所有权与材料 required scope 授权，不由“旧数据”获得豁免。开发隔离模式的历史夹具不等同生产迁移授权；需补权的真实历史数据另走可审计的明确授权流程，不静默迁移。
4. **按实际顺序定迁移号。** 先完成算法技能 V311；其后实施 G6 A–E，候选 engine V216 / skill V312；再实现 G2 完整证明许可，候选 engine V217 / skill V313。都是移交时重新确认的候选号，不建空迁移占位，不用高号绕过冲突或启用 Flyway outOfOrder。原 G2 计划的 V216/V311 仅属历史候选，后续实现遵从本裁决及当时实际最大版本。
5. **G2 生产启用的依赖。** G6 E 是最小软件依赖，还需 F 的实际跨服务链路与真实 IAM 签收。后续 G2 许可仍必须独立验证 proof、原 call/key/attempt/合同/参数、当前 lease、取消、原批准快照和当前原批准者合法性。确认角色按该调用冻结的 confirmRoles，合法声明 EDITOR 的正例保留；ADMIN/EDITOR没有自动豁免，发起人不能代替原批准者。G6不授业务重试许可。
6. **有限初始数值。** 计划建议的内部票据≤60秒、当前决定≤5秒、验证时间 skew=0，接受为首版有限夹具与保守软件默认，必须构造注入 Clock 测边界，不靠长 sleep。它们不是设计原值、生产撤权 SLA 或跨 IAM/PG/外部业务的全局原子保证；临界点再次检查到期，缺证据不能延长旧授权。JWKS/HTTP字节与数量等界限按计划下调测试，不做资源耗尽探针。
7. **交付顺序与保护。** 当前唯一实现者先完成算法协议及独立审查、统一源码/制品与真实纵切，再交 G6 具体任务。每阶段独立红绿、真实可应用 diff/SHA 与审查；禁止通用 SERVICE/共享开发HS256/旧Actor生产降级。生产门禁 BLOCKED_IAM_SCOPE_ACCEPTANCE保持，隔离通过不自动改为accepted。只在本新工程和已授权三份执行文档推进，不改原四契约和v1.2正文，不安排工期。
8. **持久委托与交互令牌寿命分开。** 针对复审RR2，首版软件profile允许可信持久grant在其自身有效期且当次authority明确允许时跨越原门户JWT寿命。后台恢复的新动作由authority签发独立可验证的DELEGATED来源/操作期限，保留原PORTAL来源审计，不保存/重放过期用户JWT，不从调用者自报来源生成该权力。新动作仍绑定当前主体、grant、caller/target/action/resource及材料范围；跨hop不得重置这次签名期限，撤grant/当前拒绝/缺证据即拒绝。它不能给旧浏览器观察响应续期，原PORTAL SSE仍按其原token/grant边界关闭。此为待独立复核及有限真实路径验证的客户端profile选择，不是已实现或真实IAM能力确认。

无新外部环境请求。后续若发现 profile 与实际 IAM 不相容，应明确适配差异和影响的动作，保留生产阻断；不把用户缺少环境作为内部代码停工或虚构验收依据。
