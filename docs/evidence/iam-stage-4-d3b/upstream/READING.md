# Actual fixed-source reading

Spring Framework 6.2.7, Apache-2.0. `manifest.json` records original URLs, copied-from locations and actual byte SHAs; original source licenses are preserved. These are focused method reads, not a claim to read the whole framework.

- `TransactionTemplate.execute` gets the transaction, executes the callback, rolls back callback exceptions, then calls transactionManager.commit before returning its result. This is why AppService has a final local proof check after execute returns. Source: https://raw.githubusercontent.com/spring-projects/spring-framework/v6.2.7/spring-tx/src/main/java/org/springframework/transaction/support/TransactionTemplate.java ; SHA 0899e41dbe6b2d565661f6e001a7fa953f551fe63a90c7eb21b9e7f9340398db.
- `AbstractPlatformTransactionManager.commit` is final. `processCommit` invokes doCommit before callbacks and cleanupAfterCompletion. The test therefore decorates the real DataSourceTransactionManager.doCommit and pauses only after super.doCommit has completed; it does not intercept a callback and call that postcommit. SHA 060a6b97928f033a8e0caec76a96d378e4f8b7c22309d54acf832dcdcf7f3081.
- `DataSourceTransactionManager.doBegin` sets explicit isolation/manual commit and binds the holder by the same DataSource; doCommit calls actual Connection.commit. Cleanup unbinds, restores connection state and releases it. prepareTransactionalConnection can enforce read-only SQL when configured. The dedicated production template remains writable for FOR SHARE; it rejects ambient transactions and uses READ_COMMITTED. SHA 1cbf0f1a13d957ccaff5bfe3fe511cb70823445eef92a062e5d552a2ff67b135.
- `DataSourceUtils.doGetConnection` reuses the thread-bound holder and applyTimeout uses its remaining transaction deadline for JDBC Statement.setQueryTimeout. Production also sets PG statement_timeout/lock_timeout; the test records same-connection transactional SQL and actual PG row-lock blocking. SHA 9d4aefa1e4a3a3251f0231e8478267e4b7199e4dbe37f0b864b1c64d8f13aa45.
