# Engine tool-call HTTP contract

All endpoints require a signed internal service token carrying original tenant/principal. Every lookup is scoped to those verified values. No body identity is trusted.

- `POST /internal/tool-calls/register`: `{runId: public r_...,nodeInstanceId:number,attemptId:number,callSeq:number,skillVersionId:number,skillCode:string,arguments:object,idempotencyKey:string,leaseOwner:string}`. Engine computes `SHA256(numeric_run_id + ':' + node_id + ':' + callSeq + ':' + skillVersionId)`; verifies live node generation and attempt; atomically registers once. Returns `{callId:number,status,result,idempotency_key,claimed_by,claimed_lease,error_semantic,duration_ms,is_mock}`. Same key with changed canonical args is 409. Agent registers directly through same transaction service before skill execute and sends returned callId.
- `POST /internal/tool-calls/{callId}/claim`: `{owner,attemptId,leaseUntil?}`. Body leaseUntil is informational; engine takes real node lease_until. Returns above fields plus `claimed:boolean`. CAS REGISTERED→EXECUTING. SUCCEEDED returns persisted result with claimed=false (reuse; no external execution). SUBMITTED/EXECUTING expired becomes UNKNOWN, claimed=false; never blindly replay potentially committed writes. New node owner is a distinct replica UUID plus short random generation, under 64 characters.
- `POST /internal/tool-calls/{callId}/submitted`: `{owner,attemptId}`. Immediately before external dispatch; validates current live node and call claim then EXECUTING→SUBMITTED. Returns `{submitted:true,callId,status:'SUBMITTED'}`; lost claim409 means do not dispatch.
- `POST /internal/tool-calls/{callId}/fact`: `{owner,attemptId,status:SUCCEEDED|FAILED|UNKNOWN,result:ResultEnvelope,durationMs?,errorSemantic?,isMock?}`. Signed evidence always recorded in attempt_note. Only matching current live claim/current node RUNNING changes tool_call. Returns `{accepted:boolean,late:boolean,callId,status}`. Late fact accepted=false,late=true remains evidence only. Duplicate fact does not increment duration. Never commits node output or emits logical-success events.
- `GET /internal/tool-calls/{callId}`: persisted authority for recovery; returns same view. Registered/UNKNOWN do not imply permission to repeat a write.

Skill must persist its execution_fact/outbox before reporting, and retry reporting rather than running business action again. Engine logical node commit remains a separate live-generation CAS and same-transaction run_event append. Input and result JSON are stored in PG with pg: references; object storage offload is not yet implemented.

Verified on independent PostgreSQL25432: stable registration, changed-args rejection, one claim, submitted fencing, persisted fact before logical commit, SUCCEEDED fact reuse, expired submitted→UNKNOWN, late fact retained without state change, lease takeover, cancelled-node late commit rejection, concurrent single logical winner, resume request persistence, event seq rollback, tenant/principal boundary.

## V201 write approval addendum

`GET /internal/tool-calls/{callId}/approval` returns `{approved,callId,skillVersionId,parametersDigest,roles}`. Approved is true only for current live node/run/latest attempt, matching immutable call version/args, a persisted APPROVED decision and unexpired validity. Skill independently compares version/digest and never trusts body.confirmed. No approved decision means return WAITING_APPROVAL before claim/submitted/external I/O. Engine freezes roles from execution.confirmRoles and refuses a response role set different from that frozen declaration. Approval decision requires role, snapshotDigest and requestId, then requeues the same call under a new lease/attempt. V201 is additive and does not rewrite applied V200.

View also exposes runId/public ID, trigger_type, run_id, skill_version_id, skill_code, args_digest, node_instance_id and attempt_id for service-side identity/parameter checks. Only trigger_type DEBUG enables Mock.

Outbox duration accounting is idempotent per call+attempt: repeated UNKNOWN facts add no duplicate duration; a terminal reconciliation adds only the increase over that attempt's already-accounted actual execution duration. Distinct retry attempts contribute their actual execution duration separately.

## Controlled DRAFT and durable proof recovery (V202–V204)

`POST /internal/skill-draft-tests` body `{skillVersionId, inputs:{...}, requestId}` returns normal debug status including runId/status and nullable callId/controlledCallId until registration. Requires EDITOR and SERVICE. Engine constructs its own exact-contract DEBUG graph; client body flags never authorize a DRAFT. Tool authority adds `controlled_draft_skill_version_id`, `controlled_draft_skill_digest`, `controlled_draft_skill_contract` when applicable and `skill_contract_sha256` for newly frozen ordinary calls. DRAFT edits invalidate previous acceptance evidence.

Internal recovery pulls skill GET `/internal/skill-facts/{callId}` rather than accepting a caller-supplied result. Expected proof fields are factId, callId, runId(public), nodeInstanceId, skillVersionId, argsDigest, skillContractSha256, attemptId, status, result, durationMs, isMock, callKind and factSha256. factSha256 = SHA256(canonical(all fields excluding factSha256)). Ownership and all immutable identifiers are checked again inside a run → node → call transaction. Only SUCCEEDED/FAILED persistent evidence may advance an active WAITING_EXTERNAL run. Adoption records execution evidence, then READY; the driver must still commit logical output with a new lease. Failure retries persist in recovery_attempts/recovery_next_at/recovery_error. There is currently no exposed manual adopt HTTP endpoint.
